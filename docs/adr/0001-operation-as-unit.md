# 0001. 定義の単位を「操作」にし、公開範囲 × プロトコルで公開を許可する

- 状態: 承認
- 日付: 2026-11-02
- 関連: [design.md](../design.md) 2.1、4章、5章

## 背景

internal・partner・public の API や、REST・gRPC・GraphQL などを別々に書くと、同じ業務ロジックの入口が何重にもなり、型・認可・ドキュメントが食い違う。

## 決定

- 定義の単位を「操作」（エンドポイント）にし、入力・出力の型、ハンドラー、認可の宣言、公開の許可を1か所に持たせる
- 公開の許可は、公開範囲とプロトコルの組み合わせで、操作ごとに書く
- 操作の種類（Query・Command・Stream・Event）から、各プロトコルでの形を決める。URL などは上書きが要るときだけ書く

## 結果

- 業務ロジックは1つで、公開の仕方だけを宣言で増減できる
- プロトコル固有の細かい機能（REST のヘッダーの細工など）は、上書きの口を用意しない限り使えない

## 検討した代替案

- プロトコルごとに定義を書き、共通のハンドラーを呼ぶ：入口の定義が重複し、食い違いを防げない
