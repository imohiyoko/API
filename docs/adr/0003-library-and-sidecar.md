# 0003. 実行は組み込みライブラリとサイドカーの2通りにする

- 状態: 承認
- 日付: 2026-11-02
- 関連: [design.md](../design.md) 2.2

## 背景

組み込みのライブラリは速く単純だが、Go 以外のサービスでは使えない。

## 決定

- Go のサービスにはライブラリとして組み込む
- Go 以外のサービスには、同じ実行部分をサイドカー（`api sidecar`）として隣に置く。サイドカーが認証・認可・プロトコルの変換・フィールドの絞り込みを行い、本体には単純な HTTP（JSON）で渡す
- ほかの言語の薄いライブラリは、必要になってからマニフェストの上に足す

## 結果

- 認証・認可・絞り込みの実装は Go の1つだけで、どの言語でも同じ挙動になる
- サイドカーでは1回余分に通信が入る

## 検討した代替案

- 言語ごとにライブラリを作る：挙動の食い違いと保守の量が増える
- 単独の API ゲートウェイ：口を1か所に集められるが、サービスごとの組み込みより運用が重い。サイドカーで足りる間は採らない
