## M1 土台

**ゴール**：1つの定義から、公開範囲ごとの REST の口と OpenAPI が作られ、iam でユーザーを認証・認可できる。

### 含むもの

- 定義の DSL（Query・Command）とレジストリ（3章）
- マニフェストの書き出し・読み込み・検証（2.2、4.3）
- 共通の層：入力の検証、認証、認可、エラーの開示のルール（4.1、6章）
- 公開範囲ごとの listener とフィールドの絞り込み（4章）
- REST と OpenAPI 3.1 の生成（5章）
- ポートとアダプタ：インメモリ、iam（ユーザーのアクセストークン）
- CLI：`api gen`、`api check`
- CI：`go test`、govulncheck、staticcheck

### 完了条件

- [ ] `min=partner` のフィールドが public の応答と `openapi/public.yaml` に出ないテストが通る
- [ ] `Expose` の無い操作がどの口にも出ないテストが通る
- [ ] public の口で、internal にだけ出した操作が 404 になるテストが通る
- [ ] 4.3 の不正な定義を `api check` がすべて報告するテストが通る
- [ ] iam を起動した E2E で、ユーザーのトークンの検証と `authz:check` の許可・拒否が通る
- [ ] マニフェストを書き出して読み直すと同じ API になる（往復のテスト）

## M2 gRPC とサービスアカウント

**ゴール**：同じ定義が gRPC でも出せ、internal・partner の呼び出し元を iam で確かめられる。

- .proto の生成と、生成コードを使わない gRPC サーバー（5.2）
- サービスアカウントの認証・判定（iam#151、#152 が前提）
- 提携先ごとのレートリミット

## M3 サイドカー

**ゴール**：Go 以外のサービスが、マニフェストとサイドカーで同じ API を出せる。

- `api sidecar`：マニフェストを読み、本体へ HTTP（JSON）で渡す
- マニフェストを YAML で直接書く経路
- Go 以外（例：TypeScript）の本体での E2E

## M4 GraphQL

- SDL の生成と実行。フィールドの公開範囲の絞り込み
- フィールド・一覧の判定をまとめる（iam#153 が前提）

## M5 イベント

- Stream・Event の定義
- WebSocket、SSE、Webhook（署名・再送・配信先の登録）、AsyncAPI の生成

## M6 運用と拡張

- 契約の差分の検査（破壊的変更を CI で検出）
- トークンの対象の限定（iam#154 が前提）
- SOAP / WSDL（必要になったら）
